# ADR-0001: Линейный конвейер с инжектируемой LLM и проверкой цитат

**Статус:** Принято, уточнено 2026-11-27 по итогам прогонов
**Дата:** 2026-11-26
**Решают:** команда проекта
**Связано:** [ADR-0002](0002-models-and-free-tier.md) — выбор моделей и работа в лимитах бесплатного тарифа

## Контекст
Агент должен проверить документ требований по 29148/830 и выпустить отчёт, где **каждое нарушение
ссылается на конкретное место** (п. 6 ТЗ). Отчёт должен быть воспроизводим: жюри повторяет прогон
по README на бесплатном ключе Gemini.

Ограничения:
- 26 часов, 3 человека, все пишут на Python;
- бесплатный тариф Gemini: 20 запросов в сутки на модель в проекте, частые перегрузки (подробнее в ADR-0002);
- главный риск LLM-ревью — общие фразы и выдуманные цитаты;
- у всех команд одна и та же модель, поэтому отличаться можно только устройством агента.

## Решение
Один линейный конвейер `pipeline.run(path, llm) -> Report`:

```
документ ─► чтение (строки с номерами)
         ─► нарезка на требования ─────────────────────────────── 1 запрос
         ─► формальные проверки (без LLM)
         ─► проверка каждого требования, пакеты по 8 ───────────── ⌈N/8⌉ запросов
         ─► проверка набора: противоречия │ сценарии │ полнота ──── 3 запроса
         ─► grounding: цитата есть в документе? → номер строки
         ─► дедупликация (после сортировки по серьёзности)
         ─► вердикт ────────────────────────────────────────────── 1 запрос
         ─► отчёт Markdown + JSON
```

Для документа кейса (42–49 требований) это около 11 запросов и 5–7 минут на gemini-3.6-flash.

Ключевые решения:
1. **Шов `LLM`** (`validator/llm.py`): модули получают объект с методом `ask(prompt, schema)`.
   Адаптеров два: `Gemini` (прод) и `FakeLLM` (тесты), поэтому шов настоящий, а не гипотетический.
   Все LLM-проходы покрыты тестами без сети.
2. **Структурированный вывод.** LLM отвечает только по схеме `FindingDraft`. Поля `id`, `line`,
   `scope`, `source` проставляет код, а не модель. Каждый проход принимает только критерии своего
   семейства, иначе в таблицах отчёта рядом с дефектом стоял бы ✓.
3. **Grounding.** Находка без дословной цитаты из документа или с неизвестным кодом критерия
   отбрасывается кодом. Номер строки берётся из совпадения, а не из ответа модели. Короткие цитаты
   ищутся начиная со строки самого требования.
4. **Проверка набора — три узких прохода вместо одного широкого:**
   - *противоречия*: каждый критерий приёмки и пример прогоняется по требованиям, цели сверяются с
     требованиями, основной документ — с дочерним, единицы и типы — между разделами;
   - *сценарии*: требования, управляющие одним поведением, проверяются на конкретных цепочках событий
     (смена настройки посреди периода, отмена/возврат, граничное значение, переход периода);
   - *полнота*: пустые и шаблонные разделы, требования без критериев приёмки, откат, версия, согласования.
5. **Вердикт с жёстким правилом.** Любая critical-находка делает «можно начинать» = нет независимо от
   ответа модели; модели это правило сообщается, чтобы текст вывода не противоречил флагам.
6. **Воспроизводимость:** `temperature=0`, кэш ответов на диске, в паспорте — модель, которая реально
   ответила, и версия агента `git describe --dirty`.

## Рассмотренные варианты

### A. Один промпт на весь документ
| Измерение | Оценка |
|---|---|
| Сложность | низкая |
| Запросов на прогон | 1 |
| Привязка к тексту | не гарантирована |
| Полнота | падает на длинных документах; противоречия между частями A и B теряются |

Не выбран как решение, но оставлен как **бейзлайн** (`eval/baseline.py`) для сравнения по `eval/score.py`.

### B. Линейный конвейер + шов LLM + grounding (выбран)
| Измерение | Оценка |
|---|---|
| Сложность | средняя, около 10 небольших модулей |
| Запросов на прогон | около 11 |
| Привязка к тексту | гарантирована кодом |
| Параллельная работа | каждый модуль развивается отдельно, общий только `models.py` |

### C. Мультиагентный фреймворк (LangGraph / CrewAI)
| Измерение | Оценка |
|---|---|
| Сложность | высокая, новая зависимость и её модель исполнения |
| Запросов на прогон | 15+: агенты переговариваются |
| Выигрыш | ТЗ его не требует: «жёсткий каркас из нескольких агентов не требуется» |

Отклонён: при лимите 20 запросов в сутки на модель не укладывается даже в один прогон с запасом.

## Что показали прогоны на документе кейса

| Наблюдение | Данные | Что изменили |
|---|---|---|
| Один широкий промпт по набору распыляет модель | gemini-3.5-flash-lite: 7 находок набора, пропущены Ф-2 ↔ критерий приёмки 2 и Ф-3 ↔ Ф-4 | Разделили на проходы «противоречия» и «полнота» |
| Конфликты между требованиями слабая модель видит только по явной процедуре | gemini-3.6-flash: Ф-3 ↔ Ф-4 пропущено в общем проходе, найдено (critical) в отдельном проходе со сценариями | Добавили проход «сценарии» |
| Большие пакеты модель просматривает поверхностно | 3.6-flash, 49 требований: пакеты по 25 → ~10 находок, по 8 → 24 | Пакеты по 8 |
| Модель копирует служебный заголовок пакета в цитату | 3 находки отброшены grounding с «line 171: …» в цитате | Метаданные отделены от строки `text:` |
| Одно противоречие цитируется с двух сторон разными проходами | дубль F-001/F-003 в одном отчёте | Дедупликация по паре требований; дубли схлопываются после сортировки, выживает более серьёзный |

Итоговый отчёт (`reports/report.md`): 42 требования, 39 нарушений, 7 critical; найдены все ключевые
противоречия документа (Ф-2 ↔ критерий приёмки, Ф-3 ↔ Ф-4, отсутствие метода чтения, GET для сохранения,
200 + ERROR ↔ 400, 403 ↔ 404).

## Компромиссы
- **B против A:** больше кода и запросов, зато каждая находка проверяема, а противоречия ищутся
  отдельными проходами. Если B не обгоняет A по метрике, меняем подход, а не полируем.
- **Grounding отбрасывает и верные находки с неточной цитатой.** Осознанный выбор: лучше меньше
  находок, но все проверяемые. Отброшенные видны в stderr — по ним правится промпт.
- **Три прохода по набору пересекаются.** Это +2 запроса и риск дублей; дубли схлопывает код.
  Иначе слабая модель теряет главные противоречия.
- **Ответы модели между прогонами немного различаются** даже при `temperature=0`: например, схема
  отката найдена в одном прогоне и пропущена в другом. Кэш делает повторный прогон с теми же
  входными данными детерминированным.

## Последствия
- Проще: тестировать LLM-модули без сети (`tests/fakes.py`), подключать веб-демо и бейзлайн
  через тот же `pipeline.run` / `Report`, менять модель флагом.
- Сложнее: менять `models.py`. Это общий контракт, только по договорённости.
- Пересмотреть: если документы станут длиннее контекста модели, придётся отдавать каждому пакету
  только релевантные куски вместо целого документа; если число запросов станет узким местом —
  объединять проходы на сильных моделях, которым узкие проходы не нужны.
